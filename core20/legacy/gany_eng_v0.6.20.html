Jovian Oscillator

An experimental time-reference study built from directly observable motion in the Galilean moons of Jupiter. This version demonstrates a bootstrap from an unknown local pulse counter: observe recurring Jovian turns, recover a recurrence in arbitrary ticks, normalize it, and only then generate an A8 phase address.

Current status: experimental / provisional. No second, wall-clock timestamp, NTP signal, ephemeris time, or programmed hertz value enters the recovery math. Conventional browser timing remains only an observer/display mechanism.

EXPERIMENTS 1 + 2 · CHECK IT YOURSELF

Two core tests · oscillator independence and holdover recovery

Run these as separate tests. Experiment 1 changes the local oscillator while Jupiter stays unchanged. Experiment 2 removes observation, lets the recovered clock coast with drift, then restores observation and recalibrates from fresh Ganymede WEST turns.

EXPERIMENT 1

Change the oscillator. Keep Jupiter.

Question: If the local pulse source changes, does the recovered Jovian structure stay the same?

  1. Press Reset entire lab.
  2. Set oscillator = 73, drift = 0/512, bench motion = 8, and recalibration = AUTO.
  3. Press Run observations. Wait for RECOVERED / LOCKED and an auto-tracked Ganymede calibration ≈ 299008 raw ticks. The independent G:E:I ratio needs a longer Ganymede observation window; if it still shows —, keep running until it populates, then pause.
RUN 1 — look for
Auto-tracked Ganymede calibration ≈ 299008 raw ticks
G:E:I = 1.000 : 2.000 : 4.000
↓ change only the oscillator · do not reset the lab ↓
  1. Set oscillator = 146. Leave drift at 0 and bench motion at 8.
  2. Press Run observations again. AUTO will discard the partly completed old-rate span and wait for two fresh G-WEST landmarks. Continue until the auto-tracked Ganymede calibration reaches ≈ 598016 raw ticks and the holdover state returns to AUTO TRACKING / LOCKED. The G:E:I ratio remains a separate slower cross-check.
RUN 2 — look for
Auto-tracked Ganymede calibration ≈ 598016 raw ticks
G:E:I = 1.000 : 2.000 : 4.000

What happened? The raw pulse count doubled because the local oscillator doubled. Jupiter did not change, and the recovered 1:2:4 structure did not change.

Why it matters: the pulse generator is not the standard. The natural recurrence calibrates the pulse generator.

Failure condition: if changing only the oscillator changes the recovered normalized Jovian structure, the isolation model is wrong.

PASS: raw ticks change · 1:2:4 survives

Experiment 2 — Holdover · restore · recalibrate

Use MANUAL first. The machine captures the G-WEST pair for you; you do not have to click at the exact turn.

  1. Recover normally until RECOVERED / LOCKED.
  2. Set recalibration mode to MANUAL.
  3. Click Simulate cloud blackout.
  4. Set Injected drift to +16 / 512 and let the local clock coast.
  5. Click Restore Jovian sensor. Watch the next G-WEST update the phase error.
  6. Click Arm manual calibration. The machine waits for two fresh G-WEST turns and then recalibrates automatically from that clean WEST→WEST span.
  7. Look for CALIBRATED, a changed Frozen calibration, and phase error returning to 000₈ states.

AUTO mode: select AUTO at any time after initial lock. It begins tracking immediately; no blackout is required. If a blackout occurs, or if the local oscillator is adjusted, AUTO discards any incomplete span and resumes only from two fresh G-WEST landmarks.

Virtual physical layer — what this lab assumes

The present browser is an observer of a hypothetical physical clock. It is not the clock authority.

LayerRole in this experiment
CPU / browser timingRuns the simulation and display only. Excluded from A8 definition.
System / wall clockNot read by the recovery engine.
Arbitrary pulse sourceProduces monotonically increasing raw ticks at an initially meaningless rate.
Jovian recurrenceExternal natural reference used to calibrate / normalize the raw pulse count.
512 phase rulerRepresentation applied after recurrence recovery; it is not the anchor.
Independent Recoverability: erase the recovered clock without erasing the simulated Jovian motion. The machine must reacquire the recurrence from raw observations and arbitrary pulse counts. Change the arbitrary oscillator increment, reset, and recover again: the raw tick span changes; the normalized Jovian recurrence must not.
Repeatability: Experiment 1 beside the oscillator controls is intentionally simple enough for any visitor to repeat. After that test, Erase recovered clock memory can be used while the Jovian sensor remains active to test reacquisition from observation rather than stored calibration.

What this simulation can and cannot claim

CAN TEST logical recovery from arbitrary pulses, turn events, recurrence, ratio checks, normalization, and 512-state representation.

ASSUMES a realizable physical oscillator, edge counter, event detector, divider / register chain, and one-way observer output.

DOES NOT CLAIM that the physical A8 clock has been built, that component tolerances are solved, or that current computers define A8 time.

Development note

Auspicious 8 is exploring a simple question: Can a physical standard be reconstructed from observable natural relationships rather than inherited administrative units?

This page is one working experiment. The primary clockwork under test is the Io–Europa–Ganymede three-body core. Callisto remains visible as a secondary slow-envelope diagnostic while its eventual A8 role remains open.

The displayed hertz values exist only because present-day speakers and browsers require them. A finalized A8 audio system would derive tone synthesis from the native A8 clock rather than define the clock from present-day hertz.

Teaser: why 512? Because 512 = 2⁹ = 8³, giving 000₈ through 777₈ as a compact three-digit phase space. Whether that becomes part of the final A8 clock remains under test.
